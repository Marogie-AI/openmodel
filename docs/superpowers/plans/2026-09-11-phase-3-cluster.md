# Phase 3 — Cluster Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the whole Phase 2 platform on a local kind cluster with production-shaped structure: Calico CNI, Envoy Gateway (Gateway API) with cert-manager TLS, five namespaces with Pod Security Admission, Kustomize base + overlays, StatefulSets for data, PVC + pull Job for model weights, migrate Job + initContainer gate, probes, resource limits, Secrets, default-deny NetworkPolicies.

**Architecture:** One kind node (Docker Desktop is at 8GB; monitoring waits for Phase 4). Host ports 80/443 map to node ports 30080/30443 served by Envoy Gateway (NodePort). `kubernetes/base` holds every manifest across namespaces; `overlays/dev` adds kind-specific bits (image tag, secretGenerator from git-ignored env files). Scripts wrap cluster lifecycle and deploy. App gets three small Phase 3 changes: `/ready` pings Redis, shutdown flush bounded, `date_trunc` pinned to UTC.

**Tech Stack:** kind, Calico (Tigera operator), Envoy Gateway (Helm OCI chart), cert-manager (Helm), Gateway API v1, Kustomize (kubectl -k), kubectl, Helm (consumer only), k6 (installed now, used in Phase 4).

**Spec:** `docs/specs/2026-09-10-openmodel-design.md` (Decisions table, Target architecture, Postgres operations, Phase 3 row). Phases 1-2 are on `master`.
