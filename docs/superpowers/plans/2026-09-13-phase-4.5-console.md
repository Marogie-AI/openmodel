# Phase 4.5 — Developer Console (frontend)

## Context

The OpenModel platform (Phases 1-4, merged to `master`, pushed to `Marogie-AI/openmodel`)
has no UI. Every demo is curl: mint a key through three admin calls, paste it into a
`curl -N`, read SSE by eye, and check usage with a fourth call. A small console makes the
platform demonstrable and exercises the API the way a real customer would.

Decisions taken with the user:

- **Scope: full console** — chat, keys, usage, admin.
- **Serving: static files from the API pod.** No new Deployment, no new image, no CORS.
- **Stack: Vite + React + TypeScript**, bun (per global instructions).
- **No GraphQL.** The backend is REST and OpenAI-compatible; `/v1/chat/completions` must
  stay REST+SSE because official-SDK compatibility is a binding spec decision. A GraphQL
  layer would be a second API surface over eight endpoints, and could not carry the
  streaming endpoint without duplicating it. Data fetching uses TanStack Query over REST.
- **Admin token in memory only.** It is one shared secret granting control of every tenant;
  it is never written to localStorage and the UI says so.
- **Reachable at `https://api.openmodel.test/app`** — one new match in the HTTPRoute.

### What the exploration established (drives the design)

| Fact | Source | Consequence |
|---|---|---|
| No CORS middleware anywhere | `api/app/main.py:134-135` | Console must be same-origin. Dev uses a Vite proxy, not CORS. |
| Gateway routes only `/v1`, `/api`, `/admin`, exact `/health`, `/ready`; everything else 404s at Envoy | `kubernetes/base/edge/routes.yaml:23-38` | `/app` needs an explicit match or the console is unreachable. |
| No `StaticFiles`, no template engine, no frontend asset anywhere | `api/app/`, `api/pyproject.toml:7-20` | Everything here is new; nothing to reuse or break. |
| Docker build context is `api/` | `api/Dockerfile`, `compose.yaml:58`, `scripts/deploy.sh:14` | Bundling a `web/` build into the image requires moving the context to the repo root. This is the one structural change. |
| Raw API key is returned exactly once, at creation | `api/app/routes/admin.py:145`, `api/app/routes/keys.py:39` | The create-key UI must present it as one-time with a copy affordance. |
| No "who am I" endpoint; `/v1/models` returns allowed models only | `api/app/routes/models.py:10-21` | Console cannot show plan, rpm or org without one small addition (`GET /api/me`). |
| SSE: `data: {json}\n\n`, terminator `data: [DONE]`, in-stream errors are a normal data frame carrying the error envelope, after a 200 | `api/app/sse.py:5-13`, `api/app/routes/shared.py:83-93` | The stream reader must treat a 200 as provisional and surface an error frame. |
| `X-RateLimit-*` only on routes that ran `enforce`; `/v1/models` and `/api/usage` never set them | `api/app/logging.py:85-89`, `api/app/ratelimit.py:71` | The UI shows rate headers per call, absent on those two. |
| Usage serializes `since`/`until` as `from`/`to` | `api/app/schemas/usage.py:19-20` | Client types must use the wire names. |

## Global constraints

- Frontend lives in `web/` at the repo root. bun, TypeScript, no `any`.
- Python gates unchanged and still green: `ruff check`, `ruff format --check`,
  `mypy --strict app`, `basedpyright`, `pytest`. Frontend gates: `bun run typecheck`
  (`tsc --noEmit`), `bun run lint`, `bun test`.
- Conventional commits, one behavior each, explicit staged paths, Co-Authored-By trailer.
- No new Python runtime dependency. `StaticFiles` ships with Starlette.
- Security posture unchanged: no CORS middleware, restricted securityContext, read-only
  root filesystem (static assets are read-only, so this still holds).
- Per the standing frontend rule: screenshot every state (empty, loading, error, populated)
  from the branch's final state and record a GIF of the streaming chat.

### Task 1: Backend serving, `GET /api/me`, build-context move, edge route

The riskiest part is the build-context change, so it goes first and everything else lands
on a working image.

- `api/app/schemas/me.py`: `Me{organization_id, user_id, plan_code, requests_per_minute,
  max_concurrency, models: list[str]}` — non-secret principal fields only, no key id, no hashes.
- `api/app/routes/me.py`: `GET /api/me`, `principal: Annotated[Principal, Depends(require_principal)]`,
  returns `Me`. Mounted in the `authed` group (no rate limit; it is the console's cheap
  key-validation call).
- `api/app/config.py`: `console_dir: Path = Path("console")`, relative to the container's
  `WORKDIR /app`.
- `api/app/main.py`: after the routers, `if settings.console_dir.is_dir():
  app.mount("/app", StaticFiles(directory=settings.console_dir, html=True), name="console")`.
  Conditional so the 174 existing tests and a bare local `uvicorn` keep working with no
  bundle present. Comment why. No client-side router is used, so `html=True` is the whole
  SPA story.
- `api/Dockerfile`: new first stage `FROM oven/bun:1-alpine AS web` → `bun install
  --frozen-lockfile` → `bun run build` → `/web/dist`; builder stage gains
  `COPY --from=web /web/dist ./console`; every existing `COPY` gains the `api/` prefix.
- Root `.dockerignore` absorbing `api/.dockerignore` plus `web/node_modules`, `web/dist`,
  `.git`, `.superpowers`, `docs`, `kubernetes`, `scripts`.
- `compose.yaml` api service: `build: {context: ., dockerfile: api/Dockerfile}`.
  `scripts/deploy.sh`: `docker build -f "$REPO_ROOT/api/Dockerfile" -t "$IMAGE" "$REPO_ROOT"`.
- `kubernetes/base/edge/routes.yaml`: add `- path: {type: PathPrefix, value: /app}` with a
  comment that the console is same-origin with the API deliberately, so no CORS is needed.
- Tests: `/api/me` shape under the overridden principal; the mount is skipped when the
  directory is absent and serves `index.html` when it exists (tmp dir + `create_app`).
- Verify: `bun run build` produces `web/dist`; `docker build -f api/Dockerfile .` succeeds;
  `curl -sk https://api.openmodel.test/app/ | head` returns the HTML; `/api/me` returns the
  principal with a real key. Commits: `feat: GET /api/me`; `chore: build the console into
  the api image`; `feat: serve the console at /app`.

### Task 2: Console scaffold, API client, session handling

- `bun create vite web --template react-ts`, then strip the template to nothing.
  `vite.config.ts`: `base: "/app/"`, `server.proxy` mapping `/v1`, `/api`, `/admin` to
  `http://localhost:8000` so `bun dev` needs no CORS.
- `src/api/client.ts`: one `request()` helper — injects `Authorization: Bearer`, throws a
  typed `ApiError{status, message, type, code, requestId}` parsed from the envelope
  (`{"error":{message,type,code}}`), and returns `{data, rateLimit?: {limit, remaining,
  retryAfter?}}` read from the response headers. 429 surfaces `Retry-After`.
- `src/auth/session.ts`: API key in `localStorage` (documented as a bearer token for that
  user's own org, the same exposure as pasting it into curl); admin token in a React
  context, memory only, cleared on unload.
- `src/App.tsx`: tab state via `useState` — five tabs, no router, which is what keeps the
  static mount trivial.
- Setup tab: paste key → `GET /api/me` → on success store and show org, plan, limits, models;
  on 401 show the envelope message. Empty, loading, error and populated states all exist here.
- Tests: envelope parsing including a non-JSON body, rate-header extraction, key-format
  validation against the real regex `^om_[a-z]+_[A-Za-z0-9_-]{12}_[A-Za-z0-9_-]{32}$`.
- Commits: `chore: scaffold the console`; `feat: api client and session handling`;
  `feat: setup tab`.

### Task 3: Chat tab with streaming

- `src/api/stream.ts`: `streamChat(body, signal)` — `fetch` + `ReadableStream`, a line
  buffer that splits on `\n\n`, strips the `data: ` prefix, stops at `[DONE]`, and yields
  either a chunk or a typed error when a frame carries the error envelope. Must handle a
  frame split across reads. `AbortSignal` for the stop button.
- Chat tab: model picker from `/v1/models`, message list, streaming toggle, temperature and
  max_tokens, stop button, per-call footer showing prompt/completion tokens, latency,
  `X-RateLimit-Remaining` and `X-Request-ID`.
- A 429 renders the retry-after and the limit rather than a generic failure; an in-stream
  error renders inline in the assistant bubble.
- Tests (vitest): the framing cases — multi-frame single read, frame split across reads,
  error frame then `[DONE]`, terminator without trailing newline.
- Commits: `feat: sse reader`; `feat: chat tab`.

### Task 4: Keys and Usage tabs

- Keys: `GET /api/keys` table (prefix, created, revoked), create button → modal showing the
  raw key once with copy and an explicit "this is the only time it is shown", revoke with a
  confirm. Revoking the key currently in use is allowed by the API and the UI warns.
- Usage: from/to pickers defaulting to the API's own 30-day window, `group_by` selector
  (model, user, day, none), totals row, table of groups, and a minimal bar view for the day
  grouping. Uses the wire names `from`/`to`.
- TanStack Query for both, with invalidation after create and revoke.
- Commits: `feat: keys tab`; `feat: usage tab`.

### Task 5: Admin tab, runbook, evidence

- Admin: a token field that states it is held in memory only and grants control of every
  tenant; plans list and upsert, org create, user create, mint first key (raw key shown
  once). Every mutation is confirm-gated.
- `docs/runbooks/05-console.md`: build and run locally (`bun dev` + compose), deploy
  (`scripts/deploy.sh`), the bootstrap walk-through a newcomer follows (admin token → org →
  user → key → chat), and what to look at in Grafana while chatting from the console.
- Screenshots of each state and a GIF of a streaming response, per the standing rule.
- e2e: extend `api/tests/test_e2e.py` with `/app/` returning 200 and HTML.
- Commits: `feat: admin tab`; `test: e2e covers the console asset`; `docs: runbook 05 console`.

## Risks

- **Build-context move** is the one change that can break the existing deploy path. It lands
  first, alone, and is verified by a full `scripts/deploy.sh` before any console code exists.
- **Host capacity.** The cluster is already at its limit on an 8 GB Docker VM. The console
  adds only static bytes to an existing pod, but the verification steps run against a
  cluster that currently needs Prometheus and Grafana parked to pass the e2e suite.
- **Phase 5 CI** must gain the bun steps and the new build context, or the workflow will
  build an image without a console.
