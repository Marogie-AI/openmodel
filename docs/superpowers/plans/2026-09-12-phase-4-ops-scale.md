# Phase 4 — Ops + Scale Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Observe and scale the Phase 3 cluster: Prometheus + Grafana with a provisioned dashboard and alert rules, scrape targets for api / Postgres / Envoy, HPA on the custom `llm_inflight` metric via prometheus-adapter, a second model routed by the registry, k6 load tests, and a runbook that demonstrates "scaling the API is not scaling the bottleneck".

**Architecture:** kube-prometheus-stack (Helm, consumed not authored) in `openmodel-monitoring` under PSA `restricted` (node-exporter disabled, Alertmanager disabled, Prometheus 2h retention, small resources). ServiceMonitors/PodMonitors select api (8000), a postgres-exporter sidecar (9187) and Envoy (19001). NetworkPolicies gain monitoring allows. prometheus-adapter exposes `llm_inflight` as a per-pod custom metric; an HPA (2..10) targets average 2 in-flight per pod. A second Ollama Deployment (`ollama-coder`) serves `qwen2.5-coder:0.5b`; the registry ConfigMap routes to it. k6 runs from the host through the gateway.

**Tech Stack:** Helm charts prometheus-community/kube-prometheus-stack, prometheus-community/prometheus-adapter, metrics-server (kind needs `--kubelet-insecure-tls`); Grafana dashboard JSON via sidecar ConfigMap; k6.

**Spec:** `docs/specs/2026-09-10-openmodel-design.md` (Observability, Scaling, Phase 4 row, Postgres operations → Monitoring). Phases 1-3 on `master`; cluster `openmodel` running.

## Global Constraints

- Docker Desktop is still 8GB (user did not raise it). Ruling: proceed lean — no node-exporter, no Alertmanager, Prometheus retention 2h with 256Mi request / 768Mi limit, Grafana 128Mi/256Mi, kube-state-metrics 64Mi/128Mi, operator 128Mi/256Mi, adapter 64Mi/128Mi, metrics-server 64Mi/128Mi, second model 500m/768Mi → 1500m/1.5Gi. Report evictions/OOM instead of raising limits silently.
- Namespace `openmodel-monitoring` stays PSA `restricted`; every chart pod must be admitted without changing the namespace labels (set securityContexts via values; disable components that cannot comply).
- Helm only consumes charts; pin chart versions (record substitutions if a pin 404s). Values files committed under `monitoring/`. `scripts/cluster-up.sh` gains the monitoring installs (idempotent `helm upgrade --install`).
- Kustomize base/overlay conventions from Phase 3 (one file per component, comments, restricted securityContext, resources on every container, no secrets committed — Grafana admin password generated by `scripts/secrets.sh` into `grafana.env`).
- NetworkPolicies stay default-deny; add only the scrape flows and Prometheus→API-server egress. Every allow rule commented.
- Conventional commits, explicit staged paths; end each message with a Co-Authored-By trailer for the implementing model plus `Claude-Session: https://claude.ai/code/session_01NWcqgykTd7jaqTnZafZLa6`.
- Grafana and Prometheus are reached via `kubectl port-forward` only (not through the gateway).
- Metrics names are the existing ones from `api/app/metrics.py` (`http_requests_total`, `http_request_duration_seconds`, `llm_tokens_total`, `llm_inflight`, `llm_ttft_seconds`, `llm_requests_total`).
